# 案例如何支持通用原则

_证据附录；与原则正文分开阅读。_

## 原则、机制和效果是三个层次

[通用原则](<../skills/hpc-style-for-ai/references/rules.md>)按设计问题组织。[AMReX Base 解析](<base-study.md>)和[证据账本](<../evidence/base-evidence.json>)提供具体机制及限制，属于案例层。

一份源码可以证明它使用了某种接口、布局或分派方式，并帮助解释这种设计解决什么问题；它不证明这种方式适合所有算法，也不证明实际运行更快。通用原则包含工程推理与建议，不是从单一仓库形式化推出的定理。当前论据仍只有第一轮 Base 阅读，没有声称已完成多项目经验验证。

证据编号均对应[账本](<../evidence/base-evidence.json>)的固定提交、文件与行号。下表说明局部支持范围，不要求十二条原则都由这个案例证明。

| --- | --- | --- |
| G01 计算契约 | E11b 的跨类型 Copy 约束 | 类型兼容与业务数值合法性需要区分；本轮没有完整误差、守恒或可复现性审计 |
| G02 主导成本 | E08 容量复用，E13b 分块转置，E16 通信与本地工作 | 展示针对不同成本的机制；没有端到端瓶颈或加速比测量 |

| G04 抽象边界 | E01–E05 的构建职责、分布、遍历和资源接口 | 可用于解释不同变化方向；不是通用类层次蓝图 |

## 将原则迁移到其他问题

以下是用于检验抽象层级的假设场景，不是新增项目审计或已完成的实验：

- **稠密计算**：先问计算强度、数据复用与库调用边界；是否需要特化取决于稳定结构和调用次数，而不是必须自己写模板核函数。
- **稀疏或图计算**：先问不规则访问、结构复用、任务长尾与预处理摊销；不预设连续组件布局或网格分块。
- **粒子或动态任务**：先问数据重排、活跃集合、分布变化和迁移成本；容量复用与动态调度分别计算收益和代价。
- **频域或重复变换**：先问计划构建、重复次数、重排与通信；“提前绑定”可以发生在运行时准备阶段，而非必须发生在编译期。
- **Python/Fortran/其他语言工程**：先问计算边界、批量接口、复制、部署与验证；原则不要求为获得静态类型机制而更换语言。

若这些场景的回答最终都退化成“实现一个类似原库的对象体系”，说明仍在复制案例，而没有从约束推导设计。
