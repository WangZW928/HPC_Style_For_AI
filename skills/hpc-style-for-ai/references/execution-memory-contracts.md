# 数据独立性、一致性与工作完成

_按需补充 G01、G03、G04、G06、G07、G11、G12；不是额外执行框架的要求。_

本说明用于数据共享、多种表示、并行贡献或延后完成影响正确性的任务；简单同步计算可以只用[通用原则](<rules.md>)。
先确定需要保持的结果与隔离程度，再选择存储、更新和协调办法。下面按设计问题组织，不要求每个问题都增加一种对象或设施。

## 需要共享什么，又要隔离什么

先说明使用方需要的是共同观察当前数据、互不干扰地修改，还是长期保留某个确定版本。三者的独立性要求不同。
逻辑独立不必等于立即复制全部存储：不可变版本、按需复制、重建结果或分离修改区域，都可能满足目标。
选择时比较读取频率、修改比例、保留时间和容量预算；共享可能节省搬运，却需要承担适用的写入协调与版本保留责任。
若选择物理复制，还要确认读取到一致的源版本，并在完成前保护本次读取的源版本，或约束会影响它的并发修改；分配独立空间本身不保证内容独立且有效。
资源由谁保留和最后一次使用何时结束也须分开说明；共享资源的存活管理不自动等待使用者完成。

假设一个 Python 数据批处理需要保留输入版本供审计，只读版本共享可能比逐批完整复制更合适；若后续允许原地修改，就应隔离修改或保留旧版本。
这是假设性选型，不是已测收益。验证时在允许的修改发生后检查旧结果是否保持，并测试版本释放与延后消费的边界。

## 多种表示何时有效，更新如何传播

为同一逻辑数据保留不同排列、压缩形式、分区或派生索引时，先确定哪份是更新依据、哪些是可重建结果，以及有效性覆盖到哪个范围或版本。
约定写入如何被记录、依赖表示何时失效、何时更新、更新失败后保留什么状态；状态标记若依赖人工维护，就要覆盖所有修改入口。
全量重建通常较易推理，局部更新可能节省工作，却增加脏区域追踪、传播顺序和故障恢复成本。按更新比例与重复使用次数选择，而非默认维持全部副本。
布局或格式变化还需核对逻辑元素的对应关系、实际跨度、间隙、重叠和转换规则；相同形状不保证可以直接搬运相同字节。

假设分布式分区保留邻域数据，局部更新完成并不表示邻域副本已更新；应定义此次计算允许读取哪个版本，以及更新传播的消费边界。
验证可从一次局部修改开始，对照完整重建，检查受影响和未受影响区域；再加入遗漏登记、乱序传播与中途失败，核对有效性判断是否仍成立。
若省略默认初始化，除确保读取前已写入有效值，还要满足对象构造与析构责任；完整覆盖数值不替代非平凡对象的生命周期要求。

## 工作如何分配，每份贡献应出现几次

先列出输出由哪些输入贡献、每份贡献应出现几次、谁有权发布最终结果，再把这些角色映射到实际参与者。
更换分区、批次或协作方式后，检查是否漏算、重复贡献或重复发布；避免只看每个参与者内部的循环是否正确。
多阶段处理或失败重试可能重新执行同一逻辑工作。外部写入和计数应受阶段、去重或幂等约束；原子更新只解决相应访问冲突，不消除错误重数。
合并部分结果时，规定初值、空输入、组合规则、允许的次序变化和数值误差；数学可结合性与浮点逐位一致分别验证，不统一要求所有操作满足交换律。

协作资源预算同时包含共享与私有临时数据、协调状态及其有效期。在固定预算下，增大单份工作可能减少可并发工作数，也可能增加局部复用，要结合其他资源上限判断。
选择粒度时计入启动、组织、等待和负载长尾；自动选出的合法配置只是起点，不构成最优证明。
验证可给每份贡献附可检查的编号或次数，改变分区和参与者数量，与独立参照比较；同时覆盖空域、偏斜输入、重试和临时容量边界。

## 能触及、有效与已完成分别由什么保证

能访问某段数据，只说明访问路径与权限允许；数据属于所需版本、生产已经完成、结果对当前使用方可见，是另外的问题。
逐项建立生产到消费的依赖，并明确每个完成信号覆盖哪些工作、哪些使用方，以及是否包含必要的传播与可见性保证。
调用返回可能只表示工作已接受，也可能表示结果已可消费；结果的交付方式、回退处理、部署配置与观测工具都可能改变这一边界。
不同提交入口可能共享资源，也可能独立推进；先核对实际关系，既不凭对象数量推断并发，也不凭同类名称推断顺序。
局部参与者完成不意味着其他参与者或整个作业完成。集体协调还需确认成员集合与一致参与条件，避免有人提前退出而其他人持续等待。

为数据复用与释放另列最后使用条件：生产完成之后仍可能有消费者或传播操作正在读取；持有资源也不证明结果已经就绪。
验证时改变提交次序与执行延迟，比较必要依赖存在时的结果，并用受控的缺失依赖用例检验检测能力；偶然正确不构成顺序保证。
只有在依赖允许且执行系统能够取得进展时，才有重叠机会；增加待执行工作数量不证明实际重叠。

## 如何验证实际生效的选择

记录实际使用的表示、分区、工作粒度、资源共享关系和部署配置，不只保存请求参数；系统调整、回退或隐含转换可能改变它们。
围绕具体假设选择最小反例：版本修改检验独立性，局部更新检验失效传播，贡献计数检验分工，延迟扰动检验完成边界。
再覆盖边界规模、不规则输入、不同参与者数量和实际支持的执行环境；某种简单映射通过，不替代其他映射的依赖与贡献检查。
调试检查、结果回传和观测工具可能增加等待并掩盖依赖错误；在目标部署条件下复核，区分工具改变的行为与原有保证。

计时边界应对应用户需要的结果：端到端测量包含必需的转换、传播和等待，局部测量则明确排除了什么。另记峰值容量、误差或构建成本等相关约束。
报告区分机制推断、实现完成、正确性通过和性能测量；未测环境与跳过项单独列出。局部收益要回到代表性负载判断，条件改变后重新评估或撤回方案。
